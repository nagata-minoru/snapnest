# snapnest

[![CI](https://github.com/nagata-minoru/snapnest/actions/workflows/ci.yml/badge.svg)](https://github.com/nagata-minoru/snapnest/actions/workflows/ci.yml)

ローカルにある写真を、ブラウザ上で整理・検索するための写真管理アプリです。

> 開発の初期段階です。現在はフォルダ選択・写真一覧・メタデータ保存・サムネイルのキャッシュ・コレクションと検索・再接続候補の提示までを実装しています（下記「開発段階」を参照）。

## 目指すこと

- 写真の原本をコピーせず、ローカルのファイルを参照して管理する
- 写真を一覧で見て、検索し、複数のコレクションに整理できるようにする
- 写真が移動された場合も、可能な範囲で再接続を支援する
- 最初はローカルで Chrome を対象に動かし、将来は Cloudflare Pages で公開する

## 想定している機能

- サムネイル付きの写真ライブラリ（グリッド表示）
- コレクション管理
  - 1枚の写真を複数のコレクションへ登録可能
- ファイル名などを使った検索
- サムネイルの生成とキャッシュ
- ファイル移動後の再接続候補の提示

## 技術構成（予定）

| 用途 | 採用予定 |
| --- | --- |
| UI | React + TypeScript |
| スタイル | Tailwind CSS v4（画面幅に応じてサイドバーと詳細表示を重ねて開く） |
| 開発・ビルド | Vite |
| ローカルファイルへのアクセス | File System Access API（抽象化レイヤー経由） |
| メタデータ・コレクション情報 | IndexedDB |
| サムネイルキャッシュ | IndexedDB |
| 将来の公開先 | Cloudflare Pages |

File System Access API への依存をアプリ全体へ広げないため、ファイル操作は抽象化レイヤーの裏に置く予定です。対応しないブラウザ向けには、代替手段や利用可能な範囲を検討します。

## ファイルの扱い

snapnest は写真の原本をアプリ用ストレージへ複製しない設計を想定しています。ユーザーが選択・許可したフォルダやファイルへの参照を保存し、写真の情報、コレクションとの関連、サムネイルを IndexedDB に保持します。

そのため、写真本体の保存場所やバックアップ方針は既存のファイル管理に委ねられます。一方で、ブラウザのデータを消去すると、保存済みの情報や権限の状態が失われる可能性があります。

## ブラウザの権限と制約

ブラウザは安全上の理由から、任意のローカルファイルを自由に読み書きできません。snapnest でも次の制約があります。

- 最初にユーザーがフォルダまたはファイルを明示的に選択し、アクセスを許可する必要がある
- 保存したハンドルでも、ブラウザの再起動後などに権限の再確認が必要になる場合がある
- シークレットモード、ブラウザデータの削除、サイトデータの消去により、メタデータやアクセス状態が失われる場合がある
- アクセス許可を取り消しても、保存済みのサムネイルはブラウザ内に残り、許可がない間も表示される。サムネイルを消すには、このサイトのデータを削除する
- File System Access API は対応状況がブラウザごとに異なる。初期版は Chrome を主な対象とする
- Cloudflare Pages で公開しても、写真は利用者の端末内で選択・許可された範囲だけを扱う。サーバーに原本をアップロードする設計ではない
- 公開時は `app/public/_headers` の Content-Security-Policy により、通信先を配信元のサイトだけに制限する。ほかに許可する外部のサイトは、フォントを読み込む Google Fonts（`fonts.googleapis.com`・`fonts.gstatic.com`）だけで、開いたときに閲覧者の IP アドレスなどが Google に届く。写真やそのメタデータは送らない

## 写真を移動した場合

ファイルシステム上の移動や改名を、Web アプリが常に確実に追跡できるわけではありません。ハンドルが有効な間は再アクセスできる場合がありますが、移動先・操作方法・ブラウザの実装によっては参照が切れます。

参照できなくなった写真は「再接続が必要」に入ります。フォルダを再読み込みすると、保存済みのハンドルでもう一度確かめ、元の場所に戻っていれば自動で元に戻します。

移動・改名された写真は、ライブラリ内の参照できる写真から再接続の候補を探します。サイズが同じで、ファイル名か更新日時も同じ写真を候補にします。ほかのフォルダへ移した場合は、移動先のフォルダを開くと候補に加わります。候補は保存済みのサムネイルと見比べて選び、確かめてからつなぎ直します。つなぎ直すとコレクションへの所属を引き継ぎ、見つからない写真の記録はライブラリから外します。候補がなければ、写真の記録だけをライブラリから外すこともできます（原本には触れません）。

これは候補提示のための仕組みであり、同名・類似ファイルやメタデータの変化がある場合を含め、完全な自動復旧は保証しません。自動ではつなぎ直さず、候補が複数あるときや、1 つの写真が複数の見つからない写真の候補になっているときは、その旨を表示します。内容ハッシュによる比較はまだ行っていません。

## 開発段階

本体は `app/` にあります。ローカル環境で Chrome を対象に、次の順で進めています。1 から 5 は実装済みです。

1. フォルダ選択と写真一覧の表示
2. IndexedDB へのメタデータ保存
3. サムネイル生成とキャッシュ
4. コレクションと検索
5. 再接続候補の提示
6. 対応ブラウザの検証と Cloudflare Pages 公開

一覧のサムネイルは Web Worker の中で原本を縮小して作り、IndexedDB に保存します。原本のサイズか更新日時が変わったら作り直します。縮小するまでもない小さな画像はサムネイルを作らず、原本をそのまま表示します。保存済みのサムネイルは、フォルダへのアクセス許可がないときや原本が見つからないときも表示します。詳細表示には原本を使い、原本を読めないときだけ保存済みのサムネイルで代えます。

コレクションはサイドバーで作り、写真の詳細表示から写真を入れます。1 枚の写真を複数のコレクションに入れられます。コレクションには写真の複製ではなく所属だけを保存するため、コレクションを削除しても写真はライブラリに残ります。検索欄では、フォルダ名とフォルダ内のパス（ファイル名を含む）を対象に、空白で区切ったすべての語を含む写真に絞り込みます。全角・半角や大文字・小文字の違いは無視します。

本体を起動するには `app/` で次を実行します（Yarn 4 を使います）。

```sh
yarn install
yarn dev
```

`yarn test` でテスト、`yarn build` で型チェックとビルドを行います。

## 開発用モック（`mock/`）

`mock/` は、画面構成や操作感を確かめるための開発用モックです。snapnest 本体ではありません。

- 写真やコレクションはコード内の固定データで、ローカルファイルは読み込まない
- フォルダ選択などの操作は見た目だけで、機能は実装されていない
- IndexedDB や File System Access API は使わない

起動するには `mock/` で次を実行します（Yarn 4 を使います）。

```sh
yarn install
yarn dev
```
